# 弈境 · 中国象棋

## 功能边界

- 浏览器直接游玩，不需要下载客户端或注册账号。
- 联机大厅实时展示房间、对局状态、玩家和观战人数；支持按名称/房间号搜索。
- 玩家创建房间、选择执红/执黑；两位玩家都准备后开局，红方先行。
- 房间允许旁观，旁观者可聊天，但不能走棋、准备、认输或操作对局。
- 支持合法落点提示、走棋记录、翻转棋盘、认输、申请和棋、双方准备再来一局。
- 同一浏览器标签页刷新或短暂断线可恢复身份；对局中离线保留座位 90 秒，超时判负。
- 公网与局域网使用同一架构：客户端连接当前页面所属服务器，无需手动填写 WebSocket 地址。

## 技术与架构

```text
电脑 / 手机浏览器
        │ HTTP(S) + Socket.IO
        ▼
Node.js 单实例服务（监听 0.0.0.0）
        ├── 静态中文界面
        ├── 会话身份与消息校验
        ├── 实时联机大厅
        ├── 房间、玩家、旁观者与聊天
        └── 服务端象棋规则与权威棋局
```

采用 Express + Socket.IO + 原生 ES Modules。无需前端编译，便于小型服务器和局域网电脑部署。棋规模块由浏览器与服务端共享，浏览器只计算落点提示，所有实际落子均由服务端验证。客户端不上传棋盘，避免篡改局面。

## 棋规

实现车、马、炮、象、士、将/帅、兵/卒的走法，以及蹩马腿、塞象眼、象不过河、九宫限制、炮隔子吃子、将帅照面、不能送将、将军、将死和困毙判负。

这是休闲规则，不宣称符合竞赛裁判规范：同一局面（含行棋方）出现三次或连续 120 半回合无吃子且无兵卒移动时自动和棋；不实现复杂的长将/长捉责任判定。没有计时、AI、账号、积分或持久化棋谱。

## 乱阵暗棋模式

创建房间时可选择普通象棋或「乱阵暗棋」，房间内模式固定，重开时重新洗牌。暗棋沿用原有联机、观战、断线与胜负机制。

### 初始身份、归属与揭示

- 将帅固定在原位并保持明牌；其余 30 枚在全部非将帅初始棋位中全局洗牌，严格保留红黑双方各棋名数量，不按阵营分开洗牌。
- 每枚暗棋在开局时一次性按原区域设置操作标记：下半盘为红，上半盘为黑。移动前的路线使用该棋位原本的棋名及阵营，不使用真实身份。
- 相同操作标记的棋子不能互吃，不因所处区域变化反复更新标记。首次移动或被吃后翻明，按真实阵营一次性更新操作归属；此后仅按真实棋名、阵营走棋。
- 翻明后的士、相仍遵守普通象棋的九宫及己方河界约束；揭示在不合法区域的棋子可能没有合法着法，不采用标准揭棋放宽士象区域的规则。
- 合法落点和送将校验只使用移动前公开的信息。翻明后意外造成自将不回退、不重抽；对手继续行棋，可吃将获胜。其他将军、将死、困毙、认输、和棋机制沿用普通模式。

### 信息隔离与吃子记录

- 服务端的暗棋对象分离为公开的 `hidden / owner / route` 与私有的 `identity`；普通棋和明棋仅用 `type / side`。
- 客户端和观战者统一接收白名单公开快照，未揭示的 `identity` 不进入棋盘、历史、日志、合法落点或错误提示；不采用只遮挡 DOM 文字的假隐藏。
- 每步记录实际行棋方 `actor`，吃子按被吃棋子的真实阵营与 `actor` 分类，不按翻明后的移动棋阵营分类。被吃的暗棋先翻明，记录永久保留。
- 左侧「赢棋」展示行棋方吃掉的真实敌棋；右侧「乌龙」展示误吃的真实友棋。玩家默认查看自己的记录，观战者可切换红黑视角。
- 乌龙事件通过已公开的步数去重，双方和观战者同时播放：在行棋方对手的将帅当前位置浮出 `🤣🤣`，屏幕中央黑红巨字渐入渐隐。刷新或刚进入观战时不重播历史动画；动画不阻挡棋盘点击，尊重减少动态效果设置。

借鉴 PyChess 的暗棋/明棋分层与首次走棋揭示机制，但不复制其代码；跨阵营洗牌、一次性归属标记和乌龙规则以本项目约定为准。参考：https://www.pychess.org/variants/jieqi 与 https://github.com/gbtami/pychess-variants/compare/master...jieqi 。

## 会话与生命周期

- 服务端签发不可猜测的随机会话令牌，浏览器标签页保存在 sessionStorage 中；昵称可保存到 localStorage。
- 会话令牌不公开给对手或旁观者，房间快照只包含公开信息。
- 每个身份最多占用一个房间；加入房间时明确区分玩家和观战者。
- 断线后推送离线状态，重连时发送完整快照，不依赖客户端缓存的棋局。
- 对局中主动离开视为认输；意外断线保留 90 秒。等待中的空房间和结束的无人房间自动清理。
- 内存保存房间与棋局：服务重启后清空。当前版本定位单实例轻量部署，不支持直接横向扩容。
- 限制消息频率、昵称/聊天长度、房间数量与观战人数，并限制 Socket.IO 消息大小。

## 部署

- 本机：`npm install && npm start`，访问 `http://localhost:3000`。
- 局域网：同一网络下访问主机的 `http://局域网IP:3000`，防火墙放行 TCP 3000。
- 公网：Node.js 服务或 Docker 部署；Nginx 反向代理并转发 WebSocket Upgrade，公网使用 HTTPS。
- Docker 提供健康检查与自动重启策略，不把开发依赖带入镜像。
